Four Real-World E-Commerce Export Traps Hidden in data/:
1. 545 Blank Rows + 355 Mid-File Repeated Headers: Several rows literally say Order ID, Product, Quantity Ordered... right in the middle of a month! If you don't filter Order ID <> "Order ID" and <> "" BEFORE converting types, Power Query throws 355 DataFormat.Errors!
2. The Two-Portlands Trap: Purchase Address ("917 1st St, Dallas, TX 75001") serves both Portland, OR ($1,870,732) and Portland, ME ($449,758)! Always build Market = City & ", " & State so the two Portlands stay separate!
3. Midnight New Year Spillover: Sales_December_2019.csv contains 34 orders placed just after midnight on 01/01/20 ($8,670.29). All clean rows = $34,492,035.97; strict 2019 = $34,483,365.68.
4. Order Line vs. Basket Order ID: 185,950 line items belong to 178,437 distinct Order IDs (multi-item baskets like iPhone + Lightning Cable!). Always compute AOV using DISTINCTCOUNT('Sales'[Order ID])!

185,950 rows easily fit inside Excel's 1,048,576-row grid, and Excel has the exact same Power Query engine as Power BI!
Click Data → Get Data → From File → From Folder → browse to datasets/13-monthly-sales/data → click Combine → Combine & Transform Data → click OK.

In Power Query, filter Order ID to uncheck null, (blank), and Order ID. Change Quantity Ordered = Whole Number and Price Each = Currency. 5. Phase B — Complete Power BI Folder Pipeline & Charts Journey

Stage 1 & 2 — Folder Combine, Junk Removal & Address Splitting in Power Query

  1. Click Home → Get data → More… → Folder → Connect → select datasets/13-monthly-sales/data → click Combine & Transform Data → click OK. Rename the combined query to Sales.
  2. CRITICAL ORDER OF OPERATIONS: Look at Applied Steps on the right: if Power Query auto-inserted a Changed Type step that already turned repeated "Order ID" rows into Error, click the X next to Changed Type first!
  3. Click the filter arrow on Order ID → uncheck null, (blank), and Order ID → click OK. All 900 junk rows vanish cleanly!
  4. Now set Data Types: Order ID = Text, Quantity Ordered = Whole Number, Price Each = Fixed decimal number ($).
  5. Parse Order Date (MM/DD/YY HH:MM): Right-click Order Date → Change Type → Using Locale → Data Type: Date/Time, Locale: English (United States). Then select Order Date → Add Column → Date → Date Only (OrderDate) and Add Column → Time → Hour → Hour (OrderHour, 0–23).
  6. Parse Purchase Address (Solve the Two-Portlands Trap!):
    • Select Purchase Address → Transform → Split Column → By Delimiter → Comma (Each occurrence) → produces 3 columns: Street, City, and StateZip (e.g. " TX 75001").
    • Select City and StateZip → Transform → Format → Trim.
    • Select StateZip → Transform → Split Column → By Delimiter → Space → rename to State and PostalCode (Text!).
    • Click Add Column → Custom Column → Name: Market → Formula: [City] & ", " & [State]!
  7. Remove helper column Source.Name if not needed, then click Home → Close & Apply (confirm 185,950 rows!).

Stage 3 & 4 — Calendar Table & E-Commerce DAX Measures

Calendar =
VAR Base = CALENDAR ( DATE ( 2019, 1, 1 ), DATE ( 2020, 1, 1 ) )
RETURN
ADDCOLUMNS (
    Base,
    "Year", YEAR ( [Date] ),
    "MonthNum", MONTH ( [Date] ),
    "MonthShort", FORMAT ( [Date], "MMM" ),
    "YearMonth", FORMAT ( [Date], "YYYY-MM" )
)

Relate Calendar[Date] (1) → (*) Sales[OrderDate], mark as Date table, and sort MonthShort by MonthNum. Then write:

Total Revenue =
SUMX ( 'Sales', 'Sales'[Quantity Ordered] * 'Sales'[Price Each] )
// Check: $34,492,035.97 (2019 only = $34,483,365.68)

Total Units = SUM ( 'Sales'[Quantity Ordered] )
// Check: 209,079

Distinct Orders = DISTINCTCOUNT ( 'Sales'[Order ID] )
// Check: 178,437

Avg Order Value (AOV) = DIVIDE ( [Total Revenue], [Distinct Orders] )
// Check: $193.30

Items per Basket = DIVIDE ( [Total Units], [Distinct Orders] )
// Check: 1.17 units/order

8. Trainer's Troubleshooting: Common Beginner Mistakes

Mistake 1 — Leaving Power Query's auto-Changed Type step BEFORE filtering out "Order ID": That turns 355 repeated headers into row errors! Always filter text junk BEFORE changing types.
Mistake 2 — Dividing Revenue by COUNTROWS('Sales') instead of DISTINCTCOUNT('Sales'[Order ID]): That gives $185.49 (Average Line Value) instead of the true $193.30 Average Order Value!
