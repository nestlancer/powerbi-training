4. Phase A — Microsoft Excel

Goal: open the file cleanly, add only the helper columns you need, and prove one total with a PivotTable before you touch Power BI.

Step 1 — Open it the right way

Open AdventureWorks-Sales.xlsx. For the Excel pivot, start on Sales_data. You can VLOOKUP ProductKey against the Product sheet if you want category before you leave Excel.
Formats: Extended Amount → Number (2 decimals); Sales Amount → Number (2 decimals); Total Product Cost → Number (2 decimals); Unit Price → Number (2 decimals). Then View → Freeze Panes → Freeze Top Row.

Step 2 — Look for dirt

  • OrderDateKey is an integer key (such as 20190701), not a date. The real date is on Date_data.
  • Sales Amount is already extended. Do not also multiply Unit Price by Order Quantity unless you are checking the file.
  • Unit Price Discount Pct is a rate. Do not sum it.

Step 3 — No extra formula required

The columns you need are already on the sheet. Use the pivot in the next step to prove the totals before you leave Excel.

Step 4 — Pivot check

Select the data → Insert → PivotTable. Rows = SalesOrderLineKey. Values = Sum of Sales Amount. The grand total must be $109.81M. If it is not, the filter or the number format is wrong — fix that before Power BI.

Step 5 — Save

Save As 18-adventureworks-sales-clean.xlsx. Power BI should read this file, not a half-filtered view you forgot to clear.

5. Phase B — Power BI

Step 1 — Get data

Get data → Excel and load Sales_data, Product_data, Customer_data, Reseller_data, Date_data, and Sales Territory_data.

Step 2 — Power Query

Rename the main query to Sales. Set the types from Step 1. Watch Applied Steps. Then Close & Apply.

Step 3 — Model

  • Sales Order_data[SalesOrderLineKey] → Sales[SalesOrderLineKey] (one-to-many)
  • Sales Territory_data[SalesTerritoryKey] → Sales[SalesTerritoryKey] (one-to-many)
  • Reseller_data[ResellerKey] → Sales[ResellerKey] (one-to-many)
  • Product_data[ProductKey] → Sales[ProductKey] (one-to-many)
  • Customer_data[CustomerKey] → Sales[CustomerKey] (one-to-many)
  • Date_data[DateKey] → Sales[OrderDateKey] (one-to-many)

Hide key columns you do not want on the report. A hidden column can still be used by a relationship.

Step 4 — Measures

Write these as measures, not calculated columns. Replace the placeholder filter with a real value from the column.

SalesAmount = SUM('Sales'[Sales Amount])
Row Count = COUNTROWS('Sales')
ExtendedAmount = SUM('Sales'[Extended Amount])
Margin % = DIVIDE([SalesAmount], [ExtendedAmount])

Step 5 — Visuals

  • Cards for the measures in Step 4.
  • A slicer for each small category (any low-cardinality column).
  • Click a bar and confirm the other visuals filter. Use Format → Edit interactions if one visual should stay still.

6. Sign-off

  • ☐ Row count is 121,253 after the cleaning steps above.
  • ☐ Total Sales Amount is $109.81M.
  • ☐ Slicers filter every visual, and you can clear them back to the totals above.
  • ☐ Every relationship in the model view is one-to-many, from the lookup table to the fact table.

7. Stretch

  • Margin = DIVIDE(SUM(Sales[Sales Amount]) - SUM(Sales[Total Product Cost]), SUM(Sales[Sales Amount])), by Category.
  • Add a drill-through page that keeps the slicer filters and shows the underlying rows.
  • Sort a month-name column by the month number so the axis is not alphabetical.

8. Mistakes that hide the answer

  • Dragging Category onto the canvas before the Product relationship exists.
  • Relating the date table on OrderDateKey without noticing the column on the date table is called DateKey.
  • Summing an ID column, or averaging a rate that was already a percent.
  • Leaving dates as text, then wondering why the axis sorts wrong.
