Two Critical Data Secrets in walmart-openings.csv:
1. The 2-Digit Year Century Bug: Every single value in OPENDATE (Column B) uses a 2-digit year like 7/1/62! Windows/Excel/Power BI interpret 2-digit years 00–29 as 2000–2029 and 30–99 as 1930–1999 (or depending on locale, push 62 into 2062!). Luckily, Columns N, O, and P (MONTH, DAY, YEAR) store the exact 4-digit year (1962), making a 100% bulletproof date reconstruction easy!
2. Three Store Lifecycles (Do NOT Delete Blank date_super Rows!):
• 1,046 stores are traditional Wal-Mart discount stores (conversion = blank, date_super = blank).
• 1,557 stores opened as Wal-Mart and later converted to a Supercenter (conversion = 1).
• 389 stores opened from Day 1 as a Supercenter (conversion = 0).
3. Real-Estate Insight: Texas leads with 315 stores (63.5% converted to Supercenters), while California is #3 in stores (159) yet converted only 12 (7.5%) due to municipal anti-supercenter zoning ordinances!

4. Phase A — Step-by-Step in Microsoft Excel

Step A1 — Import CSV & Protect ZIP Codes

  1. Open Excel → Data → From Text/CSV → select datasets/04-walmart-openings/data/walmart-openings.csv → click Transform Data (so Excel doesn't misread OPENDATE before you see it!).
  2. Set ZIPCODE to Text, YEAR/MONTH/DAY to Whole Number, and click Close & Load.

Step A2 — Build 3 Bulletproof Helper Columns (Columns Q, R, S)

  1. Column Q — OpenDateClean (True 4-Digit Date): Instead of trusting 2-digit OPENDATE, combine YEAR (P2), MONTH (N2), and DAY (O2)! In cell Q1 type OpenDateClean, and in Q2 type:
    =DATE(P2, N2, O2)
    Format column Q as yyyy-mm-dd. Check row 2: 1962-07-01 (never 2062!).
  2. Column R — StoreHistory (3-Way Lifecycle Label): In cell R1 type StoreHistory, and in R2 type:
    =IF(D2=1, "Converted to Supercenter", IF(D2=0, "Opened as Supercenter", "Discount Wal-Mart"))
    Watch carefully: Make sure you test ISBLANK(D2) first if Excel treats blank as 0! Even safer formula:
    =IF(ISBLANK(D2), "Discount Wal-Mart", IF(D2=1, "Converted to Supercenter", "Opened as Supercenter")) ✅ (Always use ISBLANK in Excel because Excel evaluates "" = 0 as TRUE if you aren't careful!)
  3. Column S — Decade: In cell S1 type Decade, and in S2 type:
    =INT(P2/10)*10 & "s" (turns 1962 into 1960s, 1990 into 1990s).

Step A3 — PivotTable Verification

  1. Insert a PivotTable on a new sheet: Rows = STRSTATE, Columns = StoreHistory, Values = Count of storenum.
  2. Sort Grand Total Largest to Smallest: confirm TX = 315 (200 Converted, 53 Opened as Supercenter, 62 Discount Wal-Mart), FL = 175, CA = 159 (only 12 Converted!), and Grand Total = 2,992!
  3. Save as 04-walmart-openings-clean.xlsx.

5. Phase B — Complete Power BI & Charts Journey

Stage 1 & 2 — Clean Dates & Lifecycles in Power Query

  1. Click Home → Text/CSV → select data/walmart-openings.csv → Transform Data. Rename query to Stores.
  2. Build Clean Opening Date from YEAR, MONTH, DAY: Click Add Column → Custom Column → Name: OpenDate → Formula:
    #date([YEAR], [MONTH], [DAY]) → click OK, and set its type icon to Date!
  3. Build StoreHistory Conditional Column: Click Add Column → Conditional Column → Name: StoreHistory:
    • If conversion equals null → Output Discount Wal-Mart
    • Else if conversion equals 1 → Output Converted to Supercenter
    • Else → Output Opened as Supercenter → click OK.
  4. Build LocationState for Unambiguous US Mapping: Click Add Column → Custom Column → Name: LocationState → Formula: [STRSTATE] & ", USA" (prevents GA from mapping to the country Georgia in Eastern Europe!).
  5. Ensure LAT and LON are 1.2 (Decimal Number), ZIPCODE is ABC (Text), and conversion is 123 (Whole Number). Click Home → Close & Apply.

Stage 3 — Model View: Geo Categories & Calendar Table

  1. Set Geo Categories on Stores (Column tools → Data category):
    • LAT → Latitude (and Summarization = Don't summarize!)
    • LON → Longitude (and Summarization = Don't summarize!)
    • LocationState → State or Province; ZIPCODE → Postal code.
  2. Create a Date Table in Data view → New table: 
    Calendar =
ADDCOLUMNS (
    CALENDAR ( DATE ( 1962, 1, 1 ), DATE ( 2006, 12, 31 ) ),
    "Year", YEAR ( [Date] ),
    "Decade", INT ( YEAR ( [Date] ) / 10 ) * 10 & "s"
)
    Mark as date table and relate Calendar[Date] (1) → Stores[OpenDate] (*).

Stage 4 — DAX Measures (Including Your First Cumulative Running Total!)

Total Stores = COUNTROWS ( 'Stores' )
// Check: 2,992

Supercenters = CALCULATE ( [Total Stores], 'Stores'[type_store] = "Supercenter" )
// Check: 1,946

Converted Stores = SUM ( 'Stores'[conversion] )
// Check: 1,557 (SUM safely ignores nulls and 0s, counting only conversion = 1!)

Conversion Rate % = DIVIDE ( [Converted Stores], [Total Stores], 0 )
// Format: 0.0% -> Check: 52.0% overall (TX = 63.5%, CA = 7.5%)

Supercenter Share % = DIVIDE ( [Supercenters], [Total Stores], 0 )
// Format: 0.0% -> Check: 65.0%

Cumulative Stores =
CALCULATE (
    [Total Stores],
    FILTER (
        ALL ( 'Calendar' ),
        'Calendar'[Date] <= MAX ( 'Calendar'[Date] )
    )
)
// ADVANCED RUNNING TOTAL! Starts at 1 in 1962 and climbs smoothly to 2,992 in 2006!

8. Trainer's Troubleshooting: Common Beginner Mistakes

Mistake 1 — Map shows ONE single pin in the middle of Kansas: Power BI set LAT and LON to Average! Click the dropdown arrow next to LAT and LON in the Map visual wells and select Don't summarize.
Mistake 2 — Georgia (GA) lights up in Eastern Europe on the Filled Map: Two-letter state codes can collide with country names. Always append ", USA" (LocationState) and set Data Category = State or Province.
Mistake 3 — Deleting blank date_super rows: Blank means "still a traditional Wal-Mart store" — deleting blanks wipes out 1,046 real stores!
