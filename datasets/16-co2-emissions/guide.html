💡 Why do we do this?

Reason: This file ships 79 columns because it serves a research website, not your report — 66 of them are specific gases, consumption-based accounting, and share percentages your cockpit will never use. Pruning FIRST (79 → 13) shrinks the model's memory, speeds every refresh, and — most importantly for learning — leaves a Data pane you can actually read. The LEN(iso_code) = 3 filter is the elegant one-line aggregate detector from Set 09: real economies carry ISO-3 codes (USA, CHN, IND); in this export OWID's own rollups all have a blank iso_code (older OWID versions used codes like OWID_WRL) — so length = 3 cleanly separates the 223 economies from World/Asia/income-tier rows. The Power BI Matrix Visual mirrors this classification and cross-checks the totals.

Real-time example: Why the ISO rule beats name-based filtering: \"World\" and \"Asia\" are names, but there are also entities like \"Europe (excl. EU-27)\" and \"OECD (GCP)\" whose names you'd have to hunt down one by one. The code length test catches ALL of them by STRUCTURE, not by list. And the verification sums matter for a subtle honesty point: the reporting countries' 2025 total (37,748 Mt) will NEVER match OWID's World row (38,995 Mt) — the ~1,247 Mt gap is international aviation and shipping over open oceans, which belong to no country. Knowing that gap BY NAME turns an apparent bug into an insight you can cite. The PivotTable and Matrix independently confirm the 37,747.93 Mt (2025) and 37,452.85 Mt (2024) totals.

What happens if you skip it: Mistake 2: global CO₂ appears to be ~5× reality (every Chinese ton counted 6 more times across Asia, High-income, World...), and 66 unused columns bloat the pbix and bury the fields you need.

Smart-work tip: On any research-grade CSV (OWID, World Bank, Eurostat), prune to your question's columns FIRST and filter aggregates by code structure, not by name lists. And when a total \"doesn't reconcile,\" hunt for the legitimate unattributed category before assuming an error — here it's shipping & aviation. The PivotTable and Matrix are the cheap insurance that stops nonsense from ever reaching a chart.

5. Phase B — Complete Power BI Column Pruning, Unpivoting & Charts

Stage 1 & 2 — Prune `Emissions` + Unpivot `FuelBreakdown` in Power Query

  1. Import data/owid-co2-data.csv → Transform Data → rename query to Emissions.
  2. Step 1 — Prune 79 → 13 Columns: Click Home → Choose Columns → Choose Columns → uncheck (Select All Columns) → check ONLY: country, year, iso_code, population, gdp, co2, co2_per_capita, cumulative_co2, coal_co2, oil_co2, gas_co2, cement_co2, flaring_co2 → click OK.
  3. Step 2 — Filter Clean Sovereign Countries: Add Custom Column CodeLen = Text.Length([iso_code]) → filter CodeLen = 3 → remove CodeLen! Set numeric columns (`co2`..`flaring_co2`) = Decimal Number and `year` = Whole Number. Add a Composite Key CountryYear = [iso_code] & \"-\" & Text.From([year]).
  4. Step 3 — Unpivot the 5 Fuel Columns (Core Power BI Skill!):
    • Right-click Emissions in the Queries pane → Reference → rename to FuelBreakdown.
    • Keep ONLY CountryYear, year, iso_code, coal_co2, oil_co2, gas_co2, cement_co2, and flaring_co2 (filter year >= 1900 for crisp modern charts!).
    • Select the 5 fuel columns (`coal_co2`..`flaring_co2`) → right-click → Unpivot Only Selected Columns!
    • Rename Attribute → FuelType (replace `_co2` with `\"\"` and Capitalize Each Word: `Coal`, `Oil`, `Gas`, `Cement`, `Flaring`) and Value → FuelMtCO2!
  5. Click Home → Close & Apply and relate Emissions[CountryYear] (1) → (*) FuelBreakdown[CountryYear]!
💡 Why do we do this?

Reason: This stage teaches tidy data: the principle that one observation should occupy one row. The fuel columns (coal_co2, oil_co2, gas_co2...) are \"wide\" — the fuel TYPE lives in the column NAME, which is invisible to visuals. Unpivoting rotates 5 columns into (FuelType, FuelMtCO2) rows, making fuel a DATA VALUE that can sit in a Legend, a Slicer, or an axis. The CountryYear composite key then ties the exploded child table back to the parent without any ambiguity. The Power BI Matrix Visual independently confirms the 37,747.93 Mt (2025) and 37,452.85 Mt (2024) totals.

Real-time example: Feel the before/after: with 5 columns, a stacked area chart's Legend needs 5 separate fields — impossible; a \"show me Gas vs Coal only\" slicer needs 5 filters; adding a 6th fuel next year means editing every visual. After Unpivot: one FuelType field drops into Legend and it's done — the chart in Visual 2 literally cannot be built without this rotation. This wide→long reshape is the same muscle as the Set 11 genre bridge, and it's ubiquitous: monthly columns, product-category columns, survey-answer columns — all want unpivoting before analysis.

What happens if you skip it: No fuel mix chart, no fuel slicer, and a model where every new question about fuels requires hand-built DAX multiplying 5 columns — all because the data's shape fought the question instead of serving it.

Smart-work tip: Whenever you catch yourself wanting \"a slicer over columns\" or \"a legend across columns\", that's the signal to Unpivot. Column names are for the source system; values are for analysis. Reference-query + Unpivot keeps the original wide table intact for questions it still serves well.

Stage 3 & 4 — Snapshot-Safe ESG DAX Measures

Create a Calendar table if needed, but the core measures work directly on the Emissions table. Then write:

Selected Year = MAX ( 'Emissions'[year] )

Annual CO2 (Mt) =
VAR Yr = MAX ( 'Emissions'[year] )
RETURN
    CALCULATE ( SUM ( 'Emissions'[co2] ), 'Emissions'[year] = Yr )
// Check 2025: 37,747.93 Mt (220 countries) | 2024: 37,452.85 Mt

Cumulative CO2 (Mt) =
VAR Yr = MAX ( 'Emissions'[year] )
RETURN
    CALCULATE ( SUM ( 'Emissions'[cumulative_co2] ), 'Emissions'[year] = Yr )
// Check 2025: ~2,400,000 Mt | 2024: ~2,360,000 Mt

Fuel Mix Breakdown =
SUMX ( 'FuelBreakdown', 'FuelBreakdown'[FuelMtCO2] )
// Check: matches Annual CO2 (Mt) total by FuelType

ISO-3 Country Count =
DISTINCTCOUNT ( 'Emissions'[iso_code] )
// Check: 220
💡 Why do we do this?

Reason: The measures implement the tidy data + snapshot pattern. Annual CO2 (Mt) and Cumulative CO2 (Mt) pull the exact year slice (2024/2025) from the pruned 13-column table. Fuel Mix Breakdown sums the unpivoted FuelBreakdown table, proving the wide→long reshape worked. The ISO-3 Country Count validates the 220-economy filter. The Power BI Matrix Visual independently confirms the 37,747.93 Mt (2025) and 37,452.85 Mt (2024) totals.

Real-time example: The ESG director sees the 2025 total (37,747.93 Mt) vs 2024 (37,452.85 Mt) — a +0.79% growth — and the fuel mix breakdown (Coal 40%, Oil 32%, etc.). The ~1,247 Mt aviation & shipping gap is explicitly noted as an unattributed category, not an error. The PivotTable and Matrix independently confirm the totals and the ISO-3 filter.

What happens if you skip it: The model bloats with 66 unused columns, the aggregate rows inflate totals by ~5×, and the fuel mix chart is impossible to build without hand-built DAX. The PivotTable and Matrix audit is the only insurance against these errors.

Smart-work tip: Always prune first, filter by structure (ISO-3 length) second, and unpivot third. The PivotTable/Matrix cross-check is the cheap insurance that stops nonsense from ever reaching a chart.
