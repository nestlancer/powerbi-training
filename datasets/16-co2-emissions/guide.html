4. Phase A — Step-by-Step in Microsoft Excel

Step A1 — Prune 79 Columns Using Excel Power Query

Click Data → From Text/CSV → select datasets/16-co2-emissions/data/owid-co2-data.csv → click Transform Data! Click Home → Choose Columns and check ONLY: country, year, iso_code, population, gdp, co2, co2_per_capita, cumulative_co2, coal_co2, oil_co2, gas_co2, cement_co2, flaring_co2. Filter iso_code where length = 3 (or in Excel Pivot filter LEN(iso_code)=3) and verify 2024 sum = 37,452.85 Mt and 2025 sum = 37,747.93 Mt!
💡 Why do we do this?

Reason: This file ships 79 columns because it serves a research website, not your report — 66 of them are specific gases, consumption-based accounting, and share percentages your cockpit will never use. Pruning FIRST (79 → 13) shrinks the model's memory, speeds every refresh, and — most importantly for learning — leaves a Data pane you can actually read. The LEN(iso_code) = 3 filter is the elegant one-line aggregate detector from Set 09: real economies carry ISO-3 codes (USA, CHN, IND); in this export OWID's own rollups all have a blank iso_code (older OWID versions used codes like OWID_WRL) — so length = 3 cleanly separates the 223 economies from World/Asia/income-tier rows.

Real-time example: Why the ISO rule beats name-based filtering: "World" and "Asia" are names, but there are also entities like "Europe (excl. EU-27)" and "OECD (GCP)" whose names you'd have to hunt down one by one. The code length test catches ALL of them by STRUCTURE, not by list. And the verification sums matter for a subtle honesty point: the reporting countries' 2025 total (37,748 Mt) will NEVER match OWID's World row (38,995 Mt) — the ~1,247 Mt gap is international aviation and shipping over open oceans, which belong to no country. Knowing that gap BY NAME turns an apparent bug into an insight you can cite.

What happens if you skip it: Mistake 2: global CO2 appears to be ~5× reality (every Chinese ton counted 6 more times across Asia, High-income, World...), and 66 unused columns bloat the pbix and bury the fields you need.

Smart-work tip: On any research-grade CSV (OWID, World Bank, Eurostat), prune to your question's columns FIRST and filter aggregates by code structure, not by name lists. And when a total "doesn't reconcile," hunt for the legitimate unattributed category before assuming an error — here it's shipping & aviation.

5. Phase B — Complete Power BI Column Pruning, Unpivoting & Charts

Stage 1 & 2 — Prune `Emissions` + Unpivot `FuelBreakdown` in Power Query

  1. Import data/owid-co2-data.csv → Transform Data → rename query to Emissions.
  2. Step 1 — Prune 79 → 13 Columns: Click Home → Choose Columns → Choose Columns → uncheck (Select All Columns) → check ONLY: country, year, iso_code, population, gdp, co2, co2_per_capita, cumulative_co2, coal_co2, oil_co2, gas_co2, cement_co2, flaring_co2 → click OK.
  3. Step 2 — Filter Clean Sovereign Countries: Add Custom Column CodeLen = Text.Length([iso_code]) → filter CodeLen = 3 → remove CodeLen! Set numeric columns (`co2`..`flaring_co2`) = Decimal Number and `year` = Whole Number. Add a Composite Key CountryYear = [iso_code] & "-" & Text.From([year]).
  4. Step 3 — Unpivot the 5 Fuel Columns (Core Power BI Skill!):
    • Right-click Emissions in the Queries pane → Reference → rename to FuelBreakdown.
    • Keep ONLY CountryYear, year, iso_code, coal_co2, oil_co2, gas_co2, cement_co2, and flaring_co2 (filter year >= 1900 for crisp modern charts!).
    • Select the 5 fuel columns (`coal_co2`..`flaring_co2`) → right-click → Unpivot Only Selected Columns!
    • Rename Attribute → FuelType (replace `_co2` with `""` and Capitalize Each Word: `Coal`, `Oil`, `Gas`, `Cement`, `Flaring`) and Value → FuelMtCO2!
  5. Click Home → Close & Apply and relate Emissions[CountryYear] (1) → (*) FuelBreakdown[CountryYear]!
💡 Why do we do this?

Reason: This stage teaches tidy data: the principle that one observation should occupy one row. The fuel columns (coal_co2, oil_co2, gas_co2...) are "wide" — the fuel TYPE lives in the column NAME, which is invisible to visuals. Unpivoting rotates 5 columns into (FuelType, FuelMtCO2) rows, making fuel a DATA VALUE that can sit in a Legend, a Slicer, or an axis. The CountryYear composite key then ties the exploded child table back to the parent without any ambiguity.

Real-time example: Feel the before/after: with 5 columns, a stacked area chart's Legend needs 5 separate fields — impossible; a "show me Gas vs Coal only" slicer needs 5 filters; adding a 6th fuel next year means editing every visual. After Unpivot: one FuelType field drops into Legend and it's done — the chart in Visual 2 literally cannot be built without this rotation. This wide→long reshape is the same muscle as the Set 11 genre bridge, and it's ubiquitous: monthly columns, product-category columns, survey-answer columns — all want unpivoting before analysis.

What happens if you skip it: No fuel mix chart, no fuel slicer, and a model where every new question about fuels requires hand-built DAX multiplying 5 columns — all because the data's shape fought the question instead of serving it.

Smart-work tip: Whenever you catch yourself wanting "a slicer over columns" or "a legend across columns", that's the signal to Unpivot. Column names are for the source system; values are for analysis. Reference-query + Unpivot keeps the original wide table intact for questions it still serves well.

Stage 3 & 4 — Snapshot-Safe ESG DAX Measures

Selected Year = MAX ( 'Emissions'[year] )

Annual CO2 (Mt) =
VAR Yr = MAX ( 'Emissions'[year] )
RETURN
    CALCULATE ( SUM ( 'Emissions'[co2] ), 'Emissions'[year] = Yr )
// Check 2025: 37,747.93 Mt (220 countries) | 2024: 37,452.85 Mt

Cumulative CO2 (Mt) =
VAR Yr = MAX ( 'Emissions'[year] )
RETURN
    CALCULATE ( SUM ( 'Emissions'[cumulative_co2] ), 'Emissions'[year] = Yr )
// Check 2025: USA #1 (439,343 Mt) vs China #2 (298,480 Mt)!

Weighted CO2 per Capita (t) =
VAR Yr = MAX ( 'Emissions'[year] )
VAR Tonnes = CALCULATE ( SUM ( 'Emissions'[co2] ), 'Emissions'[year] = Yr ) * 1000000
VAR Pop = CALCULATE ( SUM ( 'Emissions'[population] ), 'Emissions'[year] = Yr )
RETURN DIVIDE ( Tonnes, Pop )
// Check 2025: ~4.59 t territorial (4.74 t incl. aviation/shipping)

Fuel CO2 (Mt) = SUM ( 'FuelBreakdown'[FuelMtCO2] )
💡 Why do we do this?

Reason: The subtlest measure here is Weighted CO2 per Capita. OWID ships a ready-made co2_per_capita column — and the WRONG instinct is to average it across countries. Averaging gives every country equal weight, so Malta's 5t counts as much as China's — producing a nonsense "global average" skewed by 40 tiny tax-haven islands. The correct measure rebuilds the ratio from totals: SUM(co2) × 1,000,000 ÷ SUM(population) — countries weighted by their people, exactly how "global average" should work. The snapshot pattern (MAX year + CALCULATE) then keeps annual vs cumulative vs per-capita measures all answering "the selected year".

Real-time example: The three lenses genuinely disagree — and that IS the story the ESG advisory sells: Annual: China #1 (12,417 Mt) — who's emitting now. Cumulative: USA #1 (439,343 Mt since 1750) — who built today's climate problem. Per-capita: Saudi Arabia 18.5t, USA 14.5t, India just 2.19t — who emits per person. A diplomat, a historian, and an equity advocate each need a different lens; one cockpit serving all three — without mixing them — is the entire deliverable.

What happens if you skip it: AVERAGING per-capita columns produces a wrong "world average" (tiny countries overrepresented), cumulative and annual get confused in headlines, and the deck's numbers fail the first journalist's sanity check.

Smart-work tip: When a source ships pre-computed ratios (per capita, per GDP, % share), treat them as display helpers for SINGLE rows, never as cross-row averages — always rebuild ratios from summed numerator ÷ summed denominator. The Set 07/09 weighted-vs-simple lesson, now a permanent law.

💡 Why do we do this?

Reason: This chart is the 125-year energy-history answer to "which fossil fuels drive global emissions?" — and it's ONLY possible because Unpivot made fuel a legend-able category. The stacked layers show both the total envelope (climbing toward ~38,000 Mt) and the composition of each era's emissions, which is where the policy story lives: different fuels peak, plateau, or grow at different times.

Real-time example: Read the strata like a geologist: Coal is the thick bottom layer (40.3% of 2025 emissions, 15,721 Mt — and visibly exploding after 2000 as China industrialized); Oil widens through the entire 20th century (cars, aviation); Gas grows fastest after 1990 (the "bridge fuel" era); Cement and Flaring stay thin but permanent. The cockpit insight for the ESG client: emission- reduction policy must be fuel-specific — a coal phase-out and an oil phase-out are DIFFERENT fights with different industries, timelines, and geographies, and this one chart shows why a single "reduce emissions" target is too blunt to manage.

What happens if you skip it: Without the unpivot there's no legend, so the best you can draw is five separate line charts — the reader must stack them mentally (and won't). The fuel-attribution question — the client's fourth lens — goes unanswered.

Smart-work tip: Filter the chart to 1900+ (as the stage suggests): pre-1900 years are near-zero and squash the modern era into unreadable thinness. Always give time-series charts a meaningful starting window — history that predates the question dilutes the answer.

Visual 3, 4 & 5 Annual vs. Cumulative Bar + Emitter Ribbon Chart + Per-Capita Equity Table

1. Clustered bar chart: Compare [Annual CO2 (Mt)] vs. [Cumulative CO2 (Mt)] (or use two side-by-side bars) to show how China leads today (`12.4B t`) while the US still holds #1 historical responsibility since 1750 (`439.3B t`).
2. Ribbon chart: X = `year` (`1950, 1970, 1990, 2005, 2015, 2025`), Y = `[Annual CO2 (Mt)]`, Legend = Top 8 `country`.
3. Table / Map: Contrast total vs. per-capita (`India = 2.19 t` vs `USA = 14.50 t` vs `Saudi Arabia = 18.46 t`).

💡 Why do we do this?

Reason: These three visuals are the three political framings of climate responsibility, each with its own chart type because each answers a different question. The annual-vs-cumulative bars expose the headline disagreement: China emits the most TODAY; the US emitted the most EVER — both statements are true, and the bars show why the two camps in every climate negotiation cite different numbers. The ribbon chart (Set 09's rank-shift tool) then shows WHEN leadership changed: China's ribbon crossing the US around 2006, India's overtaking Russia. The per-capita table completes the equity lens.

Real-time example: See how the cockpit serves an actual briefing: a policy advisor asked "is China the problem?" answers with the annual bar (yes, 12.4B t — 32% of the world today), then the cumulative bar (but the US owns 439B t of atmospheric history — 1.5× China's), then the per-capita table (the average American emits 14.5t/year vs India's 2.19t — 6.6×). Three charts, no single "villain" — because the honest answer is that annual, historical, and per-person responsibility are three different questions. That's precisely why the client asked for "all four lenses without double-counting."

What happens if you skip it: A single-lens deck gets argued down instantly ("but who made the mess?", "but who's emitting NOW?") — and the analyst looks partisan instead of prepared. The cockpit's power is having every lens pre-built and consistent.

Smart-work tip: When stakeholders disagree about METRICS rather than facts, build all competing lenses side-by-side in one page — it de-escalates debates by making each framing's data visible. And reuse the ribbon chart whenever "who overtook whom, and when?" is the question.
