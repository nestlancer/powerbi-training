\N Strings!MySQL null sentinel in both CSVs!
Crucial Modeling Lesson — Join on airport_id, NOT iata!
In airports.csv, 1,626 small airfields have \N instead of a 3-letter iata code — so joining on iata triggers a duplicate-key error! By contrast, airport_id (1..7,698) is 100% unique with zero blanks. Once you replace \N with null in routes[source_airport_id] and routes[dest_airport_id], both columns convert cleanly to Whole Numbers and join 1 → * to Airports[airport_id]!

4. Phase A — Step-by-Step in Microsoft Excel (XLOOKUP Across 2 Sheets)

Step A1 — Load Routes & Airports into Two Tabs

In Excel, use Data → From Text/CSV (UTF-8) to load airports.csv onto sheet Airports and routes.csv onto sheet Routes.

Step A2 — Enrich Routes Using XLOOKUP on airport_id

In Routes, add helper columns J (SourceCountry) and K (DestCountry) + L (RouteScope): 
// J2 (SourceCountry — looks up source_airport_id D2 in Airports!A:A -> returns Country D:D):
=XLOOKUP(VALUE(D2), Airports!$A$2:$A$7699, Airports!$D$2:$D$7699, "Unmatched")

// K2 (DestCountry — looks up dest_airport_id F2):
=XLOOKUP(VALUE(F2), Airports!$A$2:$A$7699, Airports!$D$2:$D$7699, "Unmatched")

// L2 (RouteScope — International vs Domestic):
=IF(OR(J2="Unmatched",K2="Unmatched"), "Unmatched", IF(J2=K2, "Domestic", "International"))
Verify with a PivotTable on RouteScope: 34,710 International (51.98%) vs. 32,061 Domestic (48.02%) across the 66,771 doubly-matched routes! Save as 12-openflights-clean.xlsx.

5. Phase B — Complete Power BI 2-Table Modeling & Charts Journey

Stage 1 & 2 — Clean Airports & Routes in Power Query

  1. Import data/airports.csv (UTF-8) → Transform Data → rename query to Airports. Select all columns (Ctrl + A) → Replace Values → Find: \N → Replace with: null. Set airport_id = Whole Number, and latitude, longitude, altitude = Decimal Number. Add Custom Column HubLabel: if [iata] = null then [name] else [iata] & " — " & [city].
  2. Click New Source → Text/CSV → select data/routes.csv → rename query to Routes. Select all columns → Replace Values \N → null. Set source_airport_id, dest_airport_id, and stops = Whole Number.
  3. In Routes, replace blank "" in codeshare with "Operated" and "Y" with "Codeshare" so legends read clearly!
  4. Click Home → Close & Apply.

Click Model view on the left rail:

Stage 4 — Role-Playing DAX Measures

Outbound Routes = COUNTROWS ( 'Routes' )
// Overall: 67,663 | When sliced by Airports[iata]="ATL": 915!

Inbound Routes =
CALCULATE (
    COUNTROWS ( 'Routes' ),
    USERELATIONSHIP ( 'Airports'[airport_id], 'Routes'[dest_airport_id] )
)
// When sliced by Airports[iata]="ATL": 911! | "LAX": 498!

Net Route Imbalance = [Outbound Routes] - [Inbound Routes]

Codeshare Share % =
DIVIDE (
    CALCULATE ( [Outbound Routes], 'Routes'[codeshare] = "Codeshare" ),
    [Outbound Routes]
)
// Check overall: 21.57% (14,597 of 67,663)

Non-Stop Share % =
DIVIDE (
    CALCULATE ( [Outbound Routes], 'Routes'[stops] = 0 ),
    [Outbound Routes]
)
// Check overall: 99.98% (67,652 of 67,663)

Connected Hubs = DISTINCTCOUNT ( 'Routes'[source_airport_id] )

8. Trainer's Troubleshooting: Common Beginner Mistakes

Mistake 1 — Joining on iata instead of airport_id: airports[iata] has 1,626 \N blanks, causing Many-to-Many join headaches! Always join on integer surrogate keys (airport_id) when available.
Mistake 2 — Duplicating the Airports table instead of using USERELATIONSHIP: Beginners often copy Airports into OriginAirports and DestAirports, but then a single Airport Slicer can't show both Outbound and Inbound together! USERELATIONSHIP solves that cleanly on one table.
