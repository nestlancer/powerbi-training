2. The client brief

Who: A software company's support director.

The ask: How many tickets do we close, how long do they take, and which countries and subscription types generate them? The ticket file does not contain the country — the customer file does.

4. Phase A — Microsoft Excel

Goal: open the file cleanly, add only the helper columns you need, and prove one total with a PivotTable before you touch Power BI.

Step 1 — Open it the right way

Open customer-feedback.xlsx and look at each sheet. Excel practice starts on Support Tickets. Power BI loads every sheet.
Formats: Date Created → Date; Escalated → Number; Duration → Number. Then View → Freeze Panes → Freeze Top Row.

Step 2 — Look for dirt

  • Date Created and Date Completed are dates. Duration is already on the ticket — check that it matches the two dates before you trust it.
  • Escalated is a flag. Decide whether it is true/false or text before you write CALCULATE.
  • Company and Subscription are tiny lookups. They exist so you practice relationships, not because they are large.

Step 3 — Helper columns

Put these in the first empty columns and fill down (double-click the fill handle).
Year   =YEAR(C2)
MonthNum   =MONTH(C2)
MonthName   =TEXT(C2,"MMM")
Excel on this machine uses a comma between arguments. If your Excel uses semicolons, swap them.

Step 4 — Pivot check

Select the data → Insert → PivotTable. Rows = Escalated. Group the date by years and put years in Columns. Values = Average of Duration. The grand total must be 3.67. If it is not, the filter or the number format is wrong — fix that before Power BI.

Step 5 — Save

Save As 17-customer-feedback-clean.xlsx. Power BI should read this file, not a half-filtered view you forgot to clear.

5. Phase B — Power BI

Step 1 — Get data

Get data → Excel and tick every sheet except an empty one. Rename Support Tickets to Tickets.

Step 2 — Power Query

Rename the main query to Tickets. Set the types from Step 1. Watch Applied Steps. Then Close & Apply.

Step 3 — Model

  • Customer Table[Customer ID] → Tickets[Customer ID] (one-to-many)
  • Customer Table[Customer ID] → Device[Customer ID] (one-to-many)
  • Geography[Geography ID] → Customer Table[Geography ID] (one-to-many)

Hide key columns you do not want on the report. A hidden column can still be used by a relationship.

Step 4 — Measures

Write these as measures, not calculated columns. Replace the placeholder filter with a real value from the column.

Duration = AVERAGE('Tickets'[Duration])
Row Count = COUNTROWS('Tickets')
Escalated = SUM('Tickets'[Escalated])
Filtered rows = CALCULATE([Row Count], 'Tickets'[Escalated] = <one of the two values>)

Step 5 — Visuals

  • Cards for the measures in Step 4.
  • Bar chart: axis Escalated, value the main measure.
  • Line chart: axis Date Created.
  • A slicer for each small category (Escalated, Duration).
  • Click a bar and confirm the other visuals filter. Use Format → Edit interactions if one visual should stay still.

6. Sign-off

  • ☐ Row count is 126,644 after the cleaning steps above.
  • ☐ Average Duration is 3.67.
  • ☐ The leading Escalated is 1 at 4.10.
  • ☐ The date axis runs from 2018-05-01 to 2018-12-01.
  • ☐ Slicers filter every visual, and you can clear them back to the totals above.
  • ☐ Every relationship in the model view is one-to-many, from the lookup table to the fact table.

7. Stretch

  • Average duration by country, which only works after Tickets → Customer → Geography.
  • Add a drill-through page that keeps the slicer filters and shows the underlying rows.
  • Sort a month-name column by the month number so the axis is not alphabetical.

8. Mistakes that hide the answer

  • A many-to-many link from Tickets to Device on Customer ID. Both sides repeat. Link each of them to Customer instead.
  • Putting Country on the ticket table by hand with a VLOOKUP you then forget to refresh.
  • Summing an ID column, or averaging a rate that was already a percent.
  • Leaving dates as text, then wondering why the axis sorts wrong.
